# 05-demo搭建：一页速记版

完整笔记：[[05-demo搭建：用Vibe Coding构建产品Demo]]

## 一句话

==把 Coze 后台逻辑变成一个能打开、能点击、能演示、能说服老板和验证用户反馈的产品 Demo。==

## 主线

`需求分析 → Coze 工作流 → Vibe coding 前台界面 → 部署链接 → 接 Coze API → 可演示 Demo`

## Demo 的目标

> [!tip] 判断标准
> Demo 的目标是“证明价值”，不是“做完产品”。

做到：

- 能打开链接。
- 能输入问题。
- 能看到像样回复。
- 能体现核心流程，含转人工。
- 看起来像个真客服。

不用做：

- 登录注册。
- 完整后台。
- 高并发。
- 上线级安全。

## Vibe coding 核心步骤

详见：[[Vibe Coding]]

`设计 → 描述 → 生成 → 预览 → 迭代 → 部署`

对应动作：

`想清界面与交互 → 写成提示词 → AI 出代码 → 看效果 → 追加修改 → 拿到链接`

## 提示词五块

详见：[[Vibe Coding五段式提示词模板]]

| 部分 | 内容 |
|---|---|
| 角色 | 你是一名前端工程师 |
| 目标 | 做一个零食电商 AI 客服聊天界面 |
| 功能 | 顶部栏、消息区、输入框、转人工提示 |
| 风格 | 暖色调、圆角、友好，像微信客服 |
| 约束 | 单页、React、假数据、简单好改 |

## 必背金句

- ==Vibe coding 省掉的是代码，不是设计。==
- ==提示词质量 = Demo 质量。==
- ==好提示词 = 清晰的设计 + 具体的描述 + 必要的示例 + 明确的约束。==
- ==Mock 数据是 Demo 的脚手架：先撑起界面，真逻辑后面再接上。==
- ==Demo 的目标是证明价值，不是做完产品。==
