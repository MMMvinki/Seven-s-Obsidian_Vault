## 这节课一句话

Prompt 不是“写一句咒语”，而是把模型节点设计成可复用、可维护、可验证的产品模块。

老师强调的核心判断：

> Prompt 工程已死，但 Prompt 它死不了。

> 我们要做的是专业，而不是使用。

## 必背公式

- 身份规则进 System，具体内容进 User。
- 转换类：信息进，信息出，不增不减。
- 理解类：信息进，判断出，识别的目的是路由。
- 问答类：只依据给定资料回答，不确定就说不确定。
- 生成类：需求进，新内容出，但不是放飞，要给角色、边界、输出约束。
- 约束防止它乱说，兜底防止它失控。
- 工程级 Prompt = 拼装 + 推理 + 防护。

## 面试前 3 分钟复述

> 我理解 Prompt 不是简单写一句指令，而是 AI 产品里的模型节点控制层。我的做法会先分 System/User：稳定的身份、规则、业务红线放 System；每轮变化的用户问题、订单、文本、知识片段放 User。然后判断任务类型，是转换、理解、问答还是生成；最后按身份、背景、目标、输入、输出、示例、限制这些模块去拼。真正工程化时，还要做变量槽、Few-shot、任务拆解、兜底和防注入，这样 Prompt 才能复用、维护和上线。
