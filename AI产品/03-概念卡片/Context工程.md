# Context 工程

> 来源章节：[[07-提示词设计：场景拆解，构建Prompt#2. Context 工程：给模型正确上下文|Context 工程]]

## 一句话定义

Context 工程解决的是“给模型什么上下文”的问题。Prompt 规定怎么做，Context 提供做这件事所需的材料。

## 常见 Context

- 用户当前问题。
- 历史对话。
- 用户画像/长期记忆。
- 订单、商品、CRM 数据。
- RAG/知识库召回片段。
- 上游节点的结构化结果。

## AI 产品经理要想的问题

- 哪些信息必须给？
- 哪些信息不能给太多，否则干扰判断？
- 上下文是直接拼进 Prompt，还是作为变量传入？
- 用户输入是否需要先做清洗、抽取、意图识别？
- 下游节点需要怎样的结构化上下文？

## 和 Prompt 的关系

Prompt 像岗位说明和工作要求，Context 像这次任务的资料包。没有 Context，模型可能答得空；Context 乱，模型可能答偏。
