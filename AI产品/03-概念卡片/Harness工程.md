# Harness 工程

> 来源章节：[[07-提示词设计：场景拆解，构建Prompt#3. Harness 工程：给模型加约束|Harness 工程]]

## 一句话定义

Harness 工程是在模型外面加约束、路由、校验、工具调用和安全边界，让模型输出能进入真实产品流程。

## 为什么需要 Harness

模型本身会生成，但产品系统需要稳定、可控、可追踪。Harness 就是把“会说话的模型”变成“能放进流程的节点”。

## 常见做法

- 前置意图识别：先判断用户要查物流、问商品、申请售后还是闲聊。
- 路由：不同意图进入不同 Prompt 或工具。
- 输出校验：检查 JSON 字段、分类标签、必填字段。
- 防注入：用户输入只能当数据，不得覆盖系统规则。
- 兜底：超范围转人工，资料不足时不编造。

老师的判断：

> 大模型本身没差别，差别在放成什么位置。

理解方式：同一个模型，放在上游可以做抽取/分类，放在中游可以做知识问答，放在下游可以做反思检查。位置不同，Prompt、Context、输出格式都不同。
