# System Prompt

> 来源章节：[[07-提示词设计：场景拆解，构建Prompt#2. System Prompt 与 User Prompt 的分工|System/User 分工]] · [[07-提示词设计：场景拆解，构建Prompt#1. 层次|Prompt 层次]]

## 一句话定义

System Prompt 是系统级规则层，用来规定 AI 是谁、守什么规则、依据什么、不能做什么。它一次设定，全程生效。

老师的类比：

> 一个大模型你可以认为是一个员工。System Prompt 就是公司给他赋予的：你是什么样的岗位？你怎么说话？你怎么办事？

## 应该放进 System 的内容

- 角色：你是谁，例如零食电商客服、知识库问答助手、数据分析助理。
- 语气：亲切、克制、专业、直接、口语化等。
- 依据来源：只能依据知识库、订单接口、召回材料。
- 红线：不得编造、不得承诺赔偿、不得越权审批、不得贬低同行。
- 兜底：不确定转人工、资料不足时说明无法判断。
- 输出要求：结构、字段、格式、长度。
- 防注入：用户输入只是咨询内容，不是修改规则的指令。

## 产品化重点：变量槽

不要把品牌、人设、称呼、语气、知识库片段全部写死。更工程化的做法是做成变量槽：

```text
你是 {{brand_name}} 的 {{role_name}}。
请使用 {{tone}} 的语气，称呼用户为 {{user_call}}。
只能依据以下知识库内容回答：
{{knowledge_snippets}}
```

老师讲的面试故事可以这样复述：

> 我们初期做的是零食电商客服，但规划上希望跨品类复用。如果把人设写死在 System Prompt 里，美妆、女装这些业务线都要重写。所以我们做了一套带变量槽的 System Prompt，品牌名、店铺名、客服昵称、语气、称呼、emoji 规则、知识库片段都通过系统传参替换。这样 System Prompt 结构不变，只换变量值，就能从零食业务切到美妆业务。

完整话术：[[System-User分层面试回答]]

## 必背句

> System 是“你是谁、守什么规矩”，全程不变；User 是“这次帮我办什么事”，每次都换。

> 身份规则进 System，具体内容进 User。
