# Prompt 自检 Checklist

> 来源章节：[[07-提示词设计：场景拆解，构建Prompt#3. 工程级 Prompt 自检|工程级 Prompt 自检]] · [[07-提示词设计：场景拆解，构建Prompt#十、工程级 Prompt 构建|工程级 Prompt 构建]]

## 1. 层次检查

- 稳定身份、规则、红线是否放在 System？
- 每次变化的问题、文本、订单、知识片段是否放在 User？
- 用户输入是否被明确标记为“数据”，而不是“指令”？

## 2. 类型检查

- 任务是转换、理解、问答还是生成？
- 写法是否匹配任务类型？
- 是否把复杂任务拆成多个节点？

## 3. 模块检查

- 身份是否清楚？
- 背景是否足够？
- 目标是否明确？
- 输入字段是否定义？
- 输出格式是否稳定？
- 是否有 Few-shot 示例？
- 限制条件是否具体？

## 4. 工程检查

- 可变内容是否做成变量槽？
- 是否有默认值和缺失处理？
- 是否能跨业务线复用？
- 是否便于开发接入和测试？

## 5. 防护检查

- 是否禁止编造？
- 是否有兜底话术？
- 是否防 Prompt 注入？
- 是否限制输出格式、长度、字段和取值范围？

## 老师的工程级总结

> 一次写对并不难，难的是规模化、稳定化、可维护。

> 工程级 Prompt 就是拼装加推理加防护。
