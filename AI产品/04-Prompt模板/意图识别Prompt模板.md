# 意图识别 Prompt 模板

> 来源章节：[[07-提示词设计：场景拆解，构建Prompt#2. 理解类：让模型判断、归类、抽取|理解类 Prompt]] · [[07-提示词设计：场景拆解，构建Prompt#八、Prompt 不只是问答：它可以做工作流节点|工作流节点]]

## 核心认知

> 识别的目的是路由，而不是改它的格式。

> 选择器里面是没有脑子，选择器本质上是一个门电路。意图识别里面才有脑细胞。

意图识别通常不是最终答案，而是把用户请求送到正确的后续流程。

## 模板

```text
你是一个电商客服意图识别器。

# 任务
根据用户输入，判断用户最主要的意图，并输出结构化结果。

# 可选意图
- product_consult：商品咨询，如口味、规格、保质期、食用方式。
- logistics_query：物流查询，如发货、到货、快递状态。
- after_sales：售后问题，如退款、退货、破损、补发。
- promotion_query：优惠活动咨询。
- other：无法归入以上类型。

# 判断规则
- 只判断用户这句话的主要意图。
- 如果同时出现多个意图，选择最需要优先处理的一个。
- 不要回答用户问题，只输出识别结果。

# 输出格式
{
  "intent": "product_consult | logistics_query | after_sales | promotion_query | other",
  "confidence": 0-1,
  "key_slots": {
    "product_name": "",
    "order_id": "",
    "issue": ""
  },
  "reason": "一句话说明判断依据"
}

# 用户输入
{{user_input}}
```

## 产品化提醒

- 如果标签值固定且规则明确，后续路由交给代码，不要让模型继续“自由发挥”。
- 如果要抽取订单号、商品名、售后原因，要给缺失字段默认值。
- 如果数值打分已有确定公式，优先用代码，不要用 LLM。
