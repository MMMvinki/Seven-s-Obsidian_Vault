# 如何讲 Vibe Coding 做 Demo

## 面试回答

> “我理解 Vibe coding 不是简单地让 AI 写代码，而是把产品经理想清楚的界面、流程、状态、交互和约束，用提示词翻译成可运行 Demo。我的做法通常是先从需求和 MVP 出发，明确 Demo 要证明什么价值；然后写一张文字版设计稿，包含页面区域、组件、状态、交互、风格和示例数据；再用五段式提示词让 AI 生成前端。第一版出来后，我不会一次性大改，而是用追加提示一次改一两个点。等界面跑通后，先用 Mock 数据撑起演示，再逐步接 Coze API，把假回复换成真实工作流。”

## 加分点

- 说清楚 Demo 和真产品的差异。
- 提到 Token 不应写死在前端。
- 提到 Mock 数据先撑界面，真实逻辑后接。
- 提到状态设计：空、加载、正常、错误、转人工。

## 一句话版本

> “Vibe coding 省掉的是代码，不是设计；产品经理真正要做的是把产品逻辑、界面状态和交互约束说清楚。”
