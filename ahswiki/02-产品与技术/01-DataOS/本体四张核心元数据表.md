# 本体四张核心元数据表

## 来源
- raw/DataOS 技术白皮书.md（3.2.4、4.3.7）
- raw/DataOS_差异化分析报告.md（1.2）

## 核心内容
DataOS 本体的技术实现落在 PostgreSQL 四张核心元数据表上：object_types（定义有什么东西）、property_definitions（每种东西有什么特征）、link_types（之间有什么关系）、action_types（能做什么操作，关联 Temporal workflow）。Hasura 自动将四张表暴露为 GraphQL API，实现"元数据驱动 API 生成"——本体定义变更后无需手写 API 代码，上层应用自动感知。对象实例存 PostgreSQL，关系数据存 Apache AGE，动作执行状态由 Temporal.io 持久化。

## 关键数据/事实
- OLTP 本体创建流程：图形化/自然语言定义结构→存为含实体类说明的 JSON→解析入四张表→生成 MD 文件→大模型解析 MD 链接 Hasura 形成 GraphQL 查询
- OLAP 流程同前三步，第四步由大模型生成标准 SQL 查询
- 约束：Hasura 只做 API 暴露，不做工作流编排（编排归 Temporal）
- 答疑口径补充：本体定义本质是"描述图结构"的元数据，图的元数据和实例都用关系库存（不引入 Neo4j 类专用图库）
- 差异化报告称此设计体现"模型即 API"的现代数据架构理念
