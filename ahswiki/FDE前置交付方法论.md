# FDE前置交付方法论

## 来源
- raw/爱化身 · 企业客户服务全景 20260526_副本.md（四、五、六、八）

## 核心内容
FDE 模式不是传统 IT 外包的"接需求做开发"。标准节奏：入场前客户老板已被说服（FDE 非 0 信任进场）；第一周不写代码——拆解 IT 资产、密集访谈（每人 30-60 分钟全程录音，还原业务决策节点而非问"哪里需要 AI"）、外部专家访谈、大模型消化情报；第二周把业务变革方案"拍到老板面前"（不是给 CTO 看，因为讨论的是业务变革）；同步自选 1-2 个易实现功能，4-6 周上线 MVP"亮肌肉"。POC 后的关键是拿回控制权：不接"下一步做哪个功能"的问题，直接铺完整变革路线图。

## 关键数据/事实
- 小队配置：1 名 FDE 组长（全职不可替换）+2-3 名核心成员 +1-3 名外协，极限编制 4-8 人全职
- FDE 组长三项素质：极强原生 AI 工具使用能力（不可协商）、基础管理素养（管 5-8 人）、强学习能力
- 画像：融资到 A 轮左右的年轻 CEO（95-00 年区间）；使命是培养几十上百个"小思谦"
- 独家能力一：4-8 人小队顶 50 人传统团队（vibe coding 一个数量级提效 + 自研 AIPM 工具 5-10 倍工作量 + 架构委员会兜底）
- 独家能力三：存量系统全面 API 化——要求客户 CTO 团队 45-60 天内完成关键系统接口化，爱化身指导、客户执行
- 技术架构委员会：6-7 位 CTO 级架构师（AI infra/知识图谱/DataOS/语音智能体/SaaS），不下场做项目、只兜底评审，"不干扰只兜底"
- "如果交付阶段我们的 FDE 会听命于对方 CTO，那就是个绝对的灾难"
