# 动作建模与Agent操作协议

## 核心内容
动作建模是 DataOS 与 Palantir 等同类产品差异化的关键：传统本体论只做静态知识描述，DataOS 把"动作"纳入本体模型，让知识可执行。每个动作类型配置前置条件（防非法操作）、执行流程（表单/审批/触发）、后置影响（状态变更与连锁触发）。核心机制是"动作模型天然形成 Agent 的操作协议"——上层 Agent 调用本体定义的动作接口而无需写死业务逻辑，业务规则变更时 Agent 不必重新开发，实现 Agent 行为与业务模型解耦。

## 关键数据/事实
- 示例流程：设备温度异常→本体语义层识别设备对象→触发报修动作→自动生成工单→通知维修人员
- 答疑口径：动作"不是简单的实体属性，而是一套标准化、有固定操作流程的公约，绑定到某个实体"，按行为组合性执行以保证数据管理安全一致
- 竞品对比中动作建模维度 DataOS 得 5 分，领先百度胜算（4 分）；火山引擎 DataAgent 不支持动作建模
- 典型动作：设备启用/停用/报修/报废，工单下发/转派/处理/关闭，人员入职/调岗/离职
- 理论定位：从操作语义学看，动作定义状态转换的合法路径（状态机规范描述）
