# 本体路线选型逻辑

## 来源
- raw/DataOS答疑相关 20260603.md（维度一、二、七）

## 核心内容
面对"为什么走本体而不走 RAG/SQL/SFT"的客户质疑，爱化身的回答：本体让模型用自然语言描述整个数据，形成随时可注入上下文的 context，在传统 RAG 和裸 SQL 之间加一层做理解和组装；SFT 微调路线"我们走过，走不通"；被 Palantir 验证过、当前成功概率最高的是本体。与知识图谱的区别：概念从图谱衍生，但对象/关系/动作是人为规定的固定抽象分类，底下具体字段随企业数据自动变化。最终给模型的不是 OWL 形式化语言，而是详尽的本体自然语言文本。

## 关键数据/事实
- 北控项目明确劝客户别走 SFT 微调
- 与 OWL 的区别：存的是形式化关系定义，但供模型消费的是自然语言本体文本（节点-关系知识库）；OLAP 查询最终仍落到 SQL
- 多跳查询实现：本体层内部存一张关系定义 index，从 index 去数据库做跳转（"查 OID/ORAD 数据"）
- 金融反欺诈建模实例：8 个对象、10 个关系、3 类动作，大模型结合场景描述分析结果表结构自动总结
- 侨银迭代：POC/MVP 约两个月跑出闭环，整体迭代 2-3 次，第二个月搭模板+培训上一线，已有 20+ 真实场景在用
- 存储选型：试过专用图数据库（Neo4j 类），"不适合特别大量的数据、产品早期、大规模稳定性差"，改用关系库
