### 实际痛点
城市研究里有一类很常见的工作：
需要回答**跟城市空间有关的问题**——比如「这片区域哪些地方值得重点看」「某个片区的公共服务设施够不够够用」。回答这类问题，在传统工作流程上，不仅要综合人口、建筑、设施、交通等好几类数据，还需要在专业的GIS地理信息系统平台进行操作。
这主要涉及到三个痛点：
> **第一个，数据获取与接入。** 数据来源分散、格式各异，要找、要下载、要上传，还要判断这个数据到底适不适合当前这个任务。
>
> **第二个，数据处理与准备。** 字段清洗、格式转换、坐标统一、范围裁剪、质量检查——这些活技术含量不高，但最容易被低估，一个项目下来吃掉很多时间。
>
> **第三个，地理空间分析。** 就算你目标很明确，还是要在 GIS 里连续做检查、处理、空间计算、调参数、再表达成地图。复杂一点的专题要来回试好几轮。
>
> 所以结论是：**做城市研究的人需要的是一个能够通过自然语言描述需求，自动完成数据→分析→制图全链路的agent。**做城市研究的人需要的，不是一个只会回答问题的 AI，是一个能真正参与分析工作的 Agent。

### AI 解决方案
因为城市数据分析需要有真实的城市空间作为载体，所以我提供的解决方案并不是用mock数据，而是真实编排了包括”规划任务-执行动作-工具调研-上下文记忆“的四段式agent架构，支持多轮对话、意图澄清。
为了让agent能够执行空间数据分析，我提供了相应的地理信息系统工具，实现数据获取与处理、空间计算、地图控制等能力。
另外，我提供了skills体系，能够让用户把行业里稳定的分析方法和指标口径封装成可复用的专业能力，可以调用，也可以新建。
关于agent的边界？兜底不伪造 + 子进程隔离审批 + 全链路归档

### 主要功能与使用流程
这是它的工作台。
主要包括了左侧的管理面板如项目管理、数据等，右侧是agent对话框，中间是可交互的地图界面。
**左边**是图层、工具、技能、成果、数据；**中间**是地图；**右边**是跟 Agent 的对话。
>
> 整个流程是这样的：**用户提出问题 → Agent 检查数据 → 数据不全就补齐 → 用户确认计划 → 拿到成果 → 继续追问。


> **Agent 负责理解与组织**——把问题变成可执行的任务：理解目标、检查数据、制定步骤。
> **Tools 是通用执行能力**——取数、处理、空间计算、地图控制、生成成果。
> **Skills 是专业方法沉淀**——把行业里稳定的分析方法和指标口径封装成可复用的能力，可以调用，也可以新建。
> **Memory 是连续分析的上下文**——记住已经用过什么数据、生成过什么图层、前面得出过什么结论，支持接着追问。

在应用场景上，我也是聚焦高频分析场景作为demo的能力演示，核心围绕 城市空间与人的供需匹配分析。主要分为三步。首先是从城市空间角度，分析物理环境中的客观特征，例如右侧视频展示了agent去获取开源建筑数据并进行建筑功能的分析。接着还可以在该片区内分析商业的密集度与业态构成、以及包括片区内城市功能是否丰富。

### 06
接着，继续对该片区进行人群分析，包括这里的人群画像是什么？居住或就业人口有多少？哪些地方人群分布最密集、最有活力等？主要解决的是，弄清楚谁在使用这个片区，便于政府规划部门响应真实的人群需求。

### 07
最后，通过将前面进行的城市物理空间分析，例如商业攻击，来去与人群活力进行叠加分析，找出需求旺盛却供给不足的区域，识别商业服务的潜在缺口。
