## 3. 旧调研哪些能用，哪些必须修正

此前的《爱化身_深度面试研究报告》《爱化身_JD解析与简历匹配》《爱化身_一面复盘》用于发现线索和梳理问题。它们是二次分析，不是独立证据。本库已回查JD、公司材料和录音，不把旧文结论互相引用成多重证明。

| 旧表述 | 修正后的理解 | 对学习和对客的影响 |
|---|---|---|
| RAG做不到跨域/多跳 | 简单向量检索对多跳关联不足；RAG可结合查询分解、SQL、图谱和多轮检索 | 学选择组合，避免错误贬低技术路线 |
| 本体带来可预测、极低幻觉，因此结果可靠 | 本体组织语义与规则；预测还依赖专业模型，输入和映射都可能错 | 分开验证数据、推理、预测、执行 |
| 城市契合度100%，最稀缺的人 | 是有依据的优势组合，稀缺度与具体任用缺证据 | 不把机会当岗位保证，先做可迁移资产 |
| 一次面试通过证明试用没问题 | 招聘认可与在岗表现不同 | 尽早取得正式期望，按交付物验证 |
| 融资第一/第二、IPO证明公司情况确定 | 这是面试中的陈述，未取得审计或正式公告支持 | 不作为教材技术结论或对外背书 |
| 300+客户、80%研发来自北大 | PDF、官网和报道存在客户统计与团队口径差异 | 介绍时注明材料版本，入职后索要统一口径 |
| 一切传统平台都不能跨域、不能执行 | 很多数据平台/业务系统也支持集成与动作 | 比较实际需求覆盖、治理、成本、交付证据 |
| 公司唯一收费方式是许可或深度合资 | 公开理念不能确定每单合同结构 | 报价前用获批准的商业政策与合同范围 |
| 缓存数据让演示100%稳定 | 缓存降低依赖，但仍可能有环境或逻辑错误 | 演练失败恢复，说明缓存/回放状态 |

例如[官网关于页](https://www.aihuashen.com/pages/about.html)使用200多家企业，PDF第4页使用300+客户；这是计数口径或版本待确认，不应由售前自行解释为公司增长或客户流失。

## 4. 未来方向的三个假设

**假设A：跨行业售前，城市是你的首个专长。**JD未把职责限定为某行业，最符合现有岗位原文。准备方法是把城市案例做通，同时能迁移到补货或客服。

**假设B：较多参与城市服务/City OS方案。**面试关联、公司案例与官网展示支持其可能性。额外准备时空本体、资源调度、履约证据、系统接入；但不用抢跑开发整座城市平台。

**假设C：承担客户Workshop、行业本体与可交互演示资产。**与JD和你的Demo背景均匹配，且不依赖具体行业分配。这是五天投入最稳妥的方向。

没有证据给三个假设分配精确概率。可在入职第一周问主管：“我先准备了城市环卫闭环，也做了向库存补货迁移的版本。接下来一个月更希望我支持城市方向还是跨行业？哪个演示资产最值得先做成标准件？”这是确认优先级，不是要求对方再证明为什么招你。

## 5. 如何把城规优势升级成企业AI售前优势

城规训练习惯综合人口、用地、交通、设施与空间尺度；企业AI售前同样要跨业务域看对象关系。但长期规划与分钟级运行的决策频率不同：规划可接受一段时间的数据滞后，调度要判断此刻车辆是否可用；规划成果侧重分析解释，运营系统还需要状态变化、责任人和完成证明。

UrbanScope的“获取—处理—分析—制图”链条可成为前半段；新增“业务对象统一—规则约束—人工授权—工单回写—结果核验”是你需要学的后半段。这个升级很具体：把地图上的点，变成有状态、有来源、有责任、可采取动作的对象。

**自测：**看到官网“展示City OS”，能否写“City OS已部署吉隆坡”？不能。看到本体研讨会提侨银，能否用它证明人车效能提升20%具有可复制保证？不能，仍需样本、基线与范围。对方建议重点学City OS，是否应放弃通用RAG/API/SQL？不应；这些是行业方案落地的共同底层。
