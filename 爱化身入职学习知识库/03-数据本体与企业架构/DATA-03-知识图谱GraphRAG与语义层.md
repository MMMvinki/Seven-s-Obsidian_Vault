> [!abstract] 学习目标
> 能判断客户问题适合结构化查询、向量 RAG、图检索还是几种方法组合，能解释为什么图谱也会出错。P0 读第 1—4 节、案例与自测，约 20 分钟；P1 深入评估、权限及建设成本。环卫案例均为原创教学模拟，未调用 Agentrix。

## 1. P0：四个术语如何连接

**本体定义业务世界的概念、关系及约束；知识图谱表达具体对象与事实联系；语义层为使用者提供统一名称、口径和访问方式；GraphRAG 利用图结构帮助检索并组织生成答案的证据。** 它们可以结合，却不是一件事，也不是必须逐级采购的产品清单。

例如本体规定工单关联道路、合同和班组；知识图谱包含 `WO-101 → R-017 → C-05`；语义层定义“逾期”应按工单所属合同的有效规则计算；GraphRAG 沿这些关系找到工单、合同和有关条款，为“为什么这个工单逾期”组织证据。最后是否允许重新派发，还要由动作权限和业务规则检查。

图谱可以存于专门图数据库，也可以由关系表及关联表支撑。语义层既可能映射 SQL 指标，也可能映射对象查询和受控动作。它们的价值在一致含义与可用接口，而不是画出了多少节点。

公司材料出现的 OAG 可理解为公司讨论本体增强生成的表达；它不是一个可直接推导兼容性、算法性能或成熟度的统一技术标准。也不要把“RAG → GraphRAG → OAG”当成所有企业必走的升级路线。RAG 能使用内部资料；GraphRAG 也能处理外部语料，内部/外部不是二者的技术分界。相关公司来源定位见 [[数据架构来源]]。

## 2. P0：向量检索为什么有时找不全

向量 RAG 通常将文档分块，转为向量，通过查询与块之间的相似性选出候选，再交给生成模型。它擅长找表达不同但意义相近的片段，例如“雨天清洁作业有哪些限制”。关键词检索则擅长精确词、合同编号、设备代码；实际系统经常将两者混合并重排。

难点是多跳问题：“哪几个高风险道路的承包合同下月到期，而且当前责任班组没有可用车辆？”答案需要依次知道道路风险、合同有效期、班组责任、车辆状态及当前时间；这些信息可能散布多表多文档，文字相似度不保证把每一步所需事实都召回来。

图检索可以沿明确关系扩大上下文，但前提是关系正确、及时、权限允许。例如先找高风险 RoadSegment，再沿合同和责任关系取得候选 Contract 与 Team，最后查车辆状态。**多跳代表多次关联，不代表因果推理，也不保证每跳都可靠。** 如果路段和合同最初连错，后面完整的路径只是在精确传播错误。

还有一种情况：用户问“全市一共多少逾期工单”。不要从相似度最高的 20 份工单摘要推断总数。需要在授权的完整数据范围内做结构化聚合；图可以帮助定位数据与口径，但不能用局部召回冒充全量统计。

## 3. P0：三种检索方法如何选择

| 问题 | 优先方法 | 为什么 | 必须补上的条件 |
|---|---|---|---|
| C-05 合同第 8 条写了什么 | 精确编号 + 文档检索 | 需要原始条款 | 版本、页码、权限 |
| 清洗与保洁的验收差别 | 混合 RAG | 自然语言相似表达多 | 引用是否真的支持答案 |
| WO-101 为何由 T-02 处理 | 对象查询 + 关系遍历 | 需要追到责任链 | 关系有效时间 |
| 哪些项目本月反复出现漏扫 | SQL/图聚合 + 文档补证 | 需要全量统计与原因材料 | 去重、分母、主题定义 |
| 所有巡检记录呈现哪些主要问题 | 主题分析或全局图摘要 | 跨大量文档概括 | 抽样/覆盖及摘要误差 |
| 明天派哪辆车更优 | 状态查询 + 预测/优化 | 是决策问题 | 目标、约束、不确定性 |

微软 GraphRAG 的官方实现区分 local、global 等查询方式，原始论文重点讨论以图和社区摘要支撑全局性语料总结。把任何“向量库旁边加一个图数据库”的系统都称为同一种 GraphRAG，会掩盖具体算法差异。[查询概览](https://microsoft.github.io/graphrag/query/overview/) · [原始论文](https://arxiv.org/abs/2404.16130)

对售前更实用的表达是：这次用了什么图，节点和边怎么产生，检索如何利用它，为什么比基线好。不要在尚未评估前说“GraphRAG 一定比普通 RAG 准”。

## 4. P0：一次可以演示的完整证据检索

模拟客户问：“中山路为什么又没有按时整改，是不是班组不作为？”系统先把“中山路”解析为对象候选；如果有两条同名路段，要求用户选区段，不能悄悄猜。确定 `R-017` 后，读出授权范围内的本周工单，并获取当时有效的合同和责任班组。

假设找到：`WO-101` 截止 10:30、实际复核关闭 10:42；10:00 收到车辆维修事件；10:05 调度建议改派，10:25 人工批准；巡检证据时间为 10:38。系统可以陈述“按演示规则，关闭晚于期限 12 分钟；车辆不可用及改派审批发生在处置期间”。但不能直接断言“审批慢导致全部超时”或“班组不作为”，因为可能还有道路封闭、现场情况等未记录因素。

```text
查询意图
 → 实体消歧：哪一个 RoadSegment
 → 权限与时间条件
 → 路段—工单—合同—班组—车辆的有效关系
 → 精确状态与时间计算
 → 检索合同条款、审批原因及巡检证据
 → 生成结论：事实 / 计算 / 待确认原因分别展示
 → 若请求行动，再进入受控动作服务
```

一个合格答案应呈现：事实结论、相关对象 ID、证据链接、规则版本、数据截至时间、尚缺信息。引用只证明“链接存在”是不够的：原文必须确实支持所说的那句话，且处于同一对象、时间和适用范围。

## 5. P1：图谱构建是一条需要验收的数据流水线

先确定对象类型和关系模板，再从结构化系统映射确定性事实；非结构化合同可用模型抽取对象、条款和关系候选，然后做实体消歧、来源绑定与校验。原始证据必须保留，抽取结果可带“待核验/已确认”状态。不能让模型从文本猜到一条关系后就升级为官方事实。

例如“V-07 昨日协助 T-02 完成临时任务”，只支持一次协助关系，不支持“V-07 永久隶属 T-02”。关系需要明确谓词、时间、来源和可信状态。若使用自动合并，要评估错误合并和漏合并两类代价；错误合并通常会扩散到更多查询，生产写操作尤其应谨慎。

还要处理更新：合同 v3 生效时，v2 不一定删除，因为历史工单仍依赖旧版本；车辆变为维修中时，不能只更新关系数据库而让图或缓存继续显示可用。可以将精确的实时状态保留在权威业务系统，检索结果在执行前回读最新状态。图谱是可查询的业务视图，不应因为拥有图结构就自动成为所有字段的权威源。

## 6. P1：图越大，权限和成本越需要具体设计

权限既限制节点，也限制边及派生摘要。甲项目能看自己的道路，却未必能看同一供应商在乙项目的报价；图查询沿供应商关系跳到乙项目，就可能越权。检索前限制候选范围，遍历时保持授权上下文，结果生成前再检查；不能只在最终页面把乙项目名称打码。

社区摘要可能融合多个权限范围的资料。用户即使看不到底层文档，仍可能从摘要获得敏感信息。因此需要按授权边界构建摘要、在可访问范围内动态总结，或放弃复用混合摘要；权限变更也需要处理缓存、向量和摘要的失效。脱敏不能替代授权：隐藏人名不等于可以披露合同价格。

索引成本不仅是一次 Embedding 费用。需要考虑文档解析、实体抽取、关系生成、消歧审核、摘要生成、增量更新和质量评估。对于少量合同和明确问答，混合 RAG 加元数据过滤可能已经足够；只有复杂关系、多跳证据或全局问题确实造成基线瓶颈时，再增加图结构。让技术复杂度服务验收目标。

## 7. P1：怎样证明图检索值得做

先固定一组真实问题，覆盖条款查询、多跳关系、精确统计、全局总结、无答案及越权尝试，人工定义可接受答案和证据。用同一数据、权限和预算比较：关键词/向量基线、加实体元数据、加图遍历、加摘要。逐步增加能力，才能知道收益来自哪里。

评估分四层：检索层看关键证据是否召回；图层看实体、关系及有效时间是否正确；回答层看事实是否被证据支持、是否遗漏关键限定；业务层看用户是否更快找到可信结论。再记录延迟、成本、拒答和人工复核负担。不能只用大模型给自己打“90 分”。

对于多跳问题可保存黄金路径，例如 `R-017 → C-05@v3 → clause-8` 和 `R-017 → T-02@当时 → V-07@当时`。系统找到了相同名称但错误版本，不算答对。答案保留“不足以判定原因”可能是正确行为，不应为了提高答复率惩罚合理拒答。

## 8. 自测与参考答案

**题 1：** 在图中能沿三条边找出完整关系，为什么仍不能说有“因果证据链”？

**答案：** 边可能表示归属、关联或时间共现。因果判断需要机制、可识别假设或干预证据；“车辆维修与超时同时出现”不是自动因果证明。完整引用提高可追溯性，不会改变关联本身的含义。

**题 2：** 把文档抽成图后，能删掉原 PDF 吗？

**答案：** 不宜。抽取存在遗漏和误解，原文、页码、版本和哈希支撑复核、更新与争议处理；图谱应保留回到证据的路径。

**题 3：** 如何回应“我们只需要几十份制度问答，也必须做全域本体吗”？

**答案：** 先做权限、版本、引用可靠的文档问答，并用真实问题评估。若未来进入跨系统履约、责任判断和可执行动作，再逐步补上相应对象、关系与规则。不要把范围扩大当成技术先进。

**十分钟练习：** 画出回答“WO-101 为什么逾期”需要的证据路径，并给每条边标注时间和来源。

**参考答案：** 工单关联道路与合同版本；合同条款确定截止时间口径；工单事件给出提交、派发、执行、复核时间；车辆和班组信息解释资源条件；原始记录支撑事实，缺失的原因明确列为待查。最后计算逾期，不能用一段模型叙述代替计算。

## 9. 30 秒客户话术

“普通知识检索擅长找到相近的文字；您的问题还跨了道路、合同、工单和资源，我们会把这些关系明确连接，再按权限和时间取证。对数量和状态用结构化查询，对条款用原文检索，对原因区分已知事实与待核实信息。是否引入图检索，要用同一批业务问题比较效果和成本。”
