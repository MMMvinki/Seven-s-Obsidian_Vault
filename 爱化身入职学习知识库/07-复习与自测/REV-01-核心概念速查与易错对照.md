# 核心概念速查与易错对照

返回 [[00-爱化身入职学习地图]]。这是回忆入口，完整机制、例子与来源在每行母笔记中。先遮住右列尝试解释，再点回薄弱章节。

## 一条主线

**业务问题→对象与证据→规则与技术选择→受控行动→结果验证→资产复用。**一句话说不清某项技术处在链路哪里，说明还没把它与工作连接起来。

## 产品与业务建模

| 概念 | 工作中的准确理解 | 易错点与母笔记 |
|---|---|---|
| AI Native | 用AI能力重新设计任务与人机协作，不只是给原系统加问答框 | 不是任何应用必须全Agent化；[[CO-02-Agentrix产品三层架构与能力核验]] |
| Data OS | 公司产品中的数据与知识基座，连接业务语义、对象、来源与动作 | 不只向量数据库；[[CO-02-Agentrix产品三层架构与能力核验#2. 三层逐层理解]] |
| Agent OS | 组织Agent、工作流、工具、权限、状态与运行控制 | 不必是单个主Agent；同上 |
| Workforce | 面向岗位的任务能力、界面、SOP、权限与评价 | 不只是一个有岗位名字的聊天机器人；同上 |
| Ontology本体 | 定义领域中对象类型、属性、关系与约束；业务平台可进一步组织动作 | 不等同把表画成图；[[DATA-02-本体建模从对象到动作]] |
| 类型/实例 | Vehicle是一种类型，V-02是一个对象实例 | 模型定义与实际业务记录分开；同上 |
| 实体解析 | 通过可信标识、映射及复核判断跨系统记录是否同一对象 | 同名或向量相似不能证明同一实体；同上 |
| 事件/动作/状态 | 事件是发生了什么，动作是请求做什么，状态是当前处于何阶段 | “发现垃圾”“创建工单”“待接单”不同；同上 |
| 时空本体 | 对象、关系、规则随时间和空间变化，保留适用范围 | 今天的归属不能覆盖历史责任；[[CITY-02-CityOS时空数据调度与多模态设计]] |
| WBM | 公司对业务行为、后果与反馈建模的技术叙事；具体实现需按产品材料核验 | 不等同某一种RL世界模型；[[DATA-05-世界行为模型与可验证决策]] |
| 知识图谱 | 实体与关系的结构化表示，可支持关系查询 | 图谱不自动保证事实、权限和时效；[[DATA-03-知识图谱GraphRAG与语义层]] |
| 语义层 | 统一指标、对象和业务含义，使查询有明确口径 | “库存”“客户”“完成率”不能只看字段名字；同上 |
| 血缘 | 结果来自哪些源记录、转换、版本与处理步骤 | 有引用URL不等于完整血缘；[[DATA-01-数据库SQL与数据接入]] |

## 大模型与应用机制

| 概念 | 工作中的准确理解 | 易错点与母笔记 |
|---|---|---|
| Token | 模型处理文本等输入的基本编码单位之一 | Token数不等于中文字数；[[AI-01-LLM原理与模型选型]] |
| Embedding | 把对象/文本编码为向量，支持相似度等计算 | 相似不是真值或身份；同上 |
| Attention | 根据表示之间的关系加权组合信息的机制 | 不等于人类注意，也不保证事实正确；同上 |
| 预训练/SFT/LoRA | 学习通用模式、任务行为或以较少参数进行适配的不同层次 | 微调不能替代实时数据与授权；同上 |
| Prompt | 给模型的任务指令、示例与约束 | 不能替代服务器权限；[[AI-02-Prompt与上下文工程]] |
| 上下文工程 | 选择当前任务需要的指令、证据、历史、工具和状态 | 并非全部资料越长越好；同上 |
| RAG | 检索外部证据后结合生成，形成有来源的回答 | 不等同知识库本身；[[AI-03-RAG从检索到可信回答]] |
| Chunk | 检索和上下文组织的文档片段 | 固定长度不能解决表格、条款和指代；同上 |
| BM25/向量/重排 | 关键词匹配、语义候选、候选精排可互补 | 不存在所有数据通用的唯一最好路线；同上 |
| GraphRAG | 用图关系等结构增强检索/总结的一类方法或具体实现 | 微软GraphRAG是其中一种，不等于本体；[[DATA-03-知识图谱GraphRAG与语义层]] |
| Function Calling | 模型提出结构化工具请求，运行时执行后返回结果 | 生成调用不是已经执行；[[AI-04-Function Calling与API工具设计]] |
| JSON Schema | 约束结构、类型、必要字段等 | 格式合法不等于对象存在、数据真实或有权执行；同上 |
| Workflow | 系统预定义控制路径或状态转换 | 流程可嵌入LLM，不必变成自由Agent；[[AI-05-Agent工作流MCP与Skills]] |
| Agent | 依据目标与环境反馈选择下一步行动的系统 | 需停止条件、工具、状态、预算；同上 |
| MCP | 连接AI应用与工具/资源的协议体系 | 不自动打通企业全部系统，不替代业务授权；同上 |
| Skills | 可复用的方法、指令与配套资源包 | 不等于训练模型，也不自动获得权限；同上 |
| Memory | 为后续任务保留信息的机制，可有不同存储与范围 | 摘要可错，不能替代权威业务状态；[[AI-02-Prompt与上下文工程]] |

## 数据、执行与验证

| 概念 | 工作中的准确理解 | 易错点与母笔记 |
|---|---|---|
| 主键/外键/JOIN | 标识、关联与组合业务记录 | 一对多关联会扩大行数，聚合前核验粒度；[[DATA-01-数据库SQL与数据接入]] |
| ETL/ELT | 转换发生在加载前或后，选择取决于架构与治理 | 接入成功不等于数据可用；同上 |
| CDC | 从数据变化捕获增量，仍需处理顺序、删除、重复和恢复 | 不是绝对零延迟；同上 |
| 认证/授权 | 确认你是谁/你能做什么 | 已登录不代表有全域读写权；[[DATA-04-企业集成权限部署与可靠执行]] |
| RBAC/ABAC | 按角色授权/按身份、资源、环境等属性做策略判断 | 按钮不可见不代表后端不可访问；同上 |
| 幂等 | 同一请求重复处理不重复产生预期业务效果 | 同一键不同请求内容应冲突，不能无限复用；同上 |
| 乐观并发 | 用版本等条件检测读取后状态是否改变 | 审批通过后仍需重新检查资源；同上 |
| 状态机 | 定义允许的状态与转换 | 工具200、已派发、已接单、已验收不同；同上 |
| Trace/Span | 记录整条任务和各步骤的运行关系 | 审计不要求泄露模型内部思维或全部敏感原文；[[AI-06-评测可观测性与成本性能]] |
| Recall@k | 规定前k条候选中找回相关证据的程度，定义需写清 | 检索命中不代表答案有据；同上 |
| p95 | 在指定样本定义下，95%的观测延迟不高于该分位值 | 不能用平均值代替长尾体验；同上 |
| TCO/ROI | 全周期总成本/特定期间收益相对成本 | 人力分钟不是自动可兑现现金，避免收益双计；[[PRE-03-方案商业价值与技术异议]] |
| Demo/POC/Pilot/生产 | 展示价值/验证假设/小范围真实运营/持续服务 | 前一阶段成功不自动满足后一阶段；[[PRE-02-Demo工作坊与POC设计]] |
| FDE/FSE | 团队中的前线技术/交付协同角色，实际名称职责按公司定义 | 不擅自替团队设绝对职责边界；[[PRE-04-能力边界FDE协同与资产沉淀]] |

## 最后一分钟复述

“先问客户要改善什么决策，找到人、数据、规则和结果。用本体统一业务语义；问知识用检索，查状态用数据库，执行用受控工具，明确流程优先工作流。Agent和专业模型按需要加入。展示时说明依据与局限，POC用基线、反例和业务指标验证。遇到产品未知，带具体问题协同确认。”
