# 五天入职冲刺

返回 [[00-爱化身入职学习地图]]

**约束：还有5天入职，每天1–2小时。必做路径总计5小时；第二小时为可选巩固，总投入不超过10小时。**不要求入职前读完全部教材。每篇的P0表示岗位重要性，本计划从中再次选最小必读部分；不要把所有P0累加成五天任务。

==五天目标：讲清产品、画出本体、选对技术、写出POC、演示一条可信业务闭环。== 更深的工程与理论留到具体项目中按需学习。

## 第一天：知道这份岗位要你交付什么

| 时间 | 必做内容 | 产出 |
|---|---|---|
| 0–5分钟 | 不看笔记说出对岗位的理解 | 记录两个不确定点 |
| 5–25分钟 | [[CO-01-为什么录用你与岗位能力地图#2. 面试证据到底支持什么]]；[[CO-02-Agentrix产品三层架构与能力核验]]第1–4节 | 分清自己已证明与尚未验证的能力 |
| 25–50分钟 | 画“问题→数据→规则与工具→审批→任务结果”，在旁边标三层架构 | 一页产品讲解草图 |
| 50–60分钟 | 录一遍3分钟产品讲解；用本页检查标准回看 | 删除无法解释的宣传词 |

**完成标准：**不用念功能表，就能用道路投诉的例子解释Data OS、Agent OS、Workforce；知道WBM不是要自己发明的第四层；能说出一项必须向公司产品确认的能力。

**可选第二小时：**20分钟读[[CO-03-CityOS方向证据与旧材料校正]]；20分钟读[[AI-01-LLM原理与模型选型]]第1、3、4节；20分钟改写产品讲解，回答“为什么有模型还需要这个平台”。

- [ ] 产品草图完成
- [ ] 3分钟讲解完成
- [ ] 一项待产品核验问题写清

## 第二天：把业务翻译成对象、关系、事件、规则和动作

| 时间 | 必做内容 | 产出 |
|---|---|---|
| 0–5分钟 | 回忆三层架构，不翻笔记 | 找出讲不顺处 |
| 5–25分钟 | [[DATA-02-本体建模从对象到动作]]第1–5节 | 理解业务对象与状态变化 |
| 25–50分钟 | 用[[CITY-01-城市治理业务与环卫履约闭环#3. 六个核心对象的最小本体]]画六对象图 | 至少6对象、6条关系、3条规则、2个动作 |
| 50–60分钟 | 故意加入“车辆位置过期”“同一路段两个编码” | 写出处理方法 |

**完成标准：**能解释对象类型与实例；不能把同名直接判成同一实体；能分开“发现事件”“提出动作”“改变状态”；每条规则都有依据和责任人，而不是只存在于Prompt。

**可选第二小时：**20分钟读[[DATA-01-数据库SQL与数据接入]]第1、3、4节；20分钟读[[DATA-05-世界行为模型与可验证决策]]第1–4节；20分钟把本体增加来源、时间与规则版本。

- [ ] 六对象草图完成
- [ ] 规则与动作能独立说明
- [ ] 两个数据错误有处理办法

## 第三天：理解RAG、Function Calling与Agent各自做什么

| 时间 | 必做内容 | 产出 |
|---|---|---|
| 0–5分钟 | 用自己的话区分事件与动作 | 口头回忆 |
| 5–25分钟 | [[AI-03-RAG从检索到可信回答]]第1、2、5节；[[AI-04-Function Calling与API工具设计]]第1、3、4节 | 理解证据与执行是两条链 |
| 25–50分钟 | 将“查合同条款、查实时车辆、计算超时、创建工单”分别匹配技术 | 一张技术选择表与一个工具输入样例 |
| 50–60分钟 | 回答“有引用就对吗”“JSON合法就能执行吗” | 写出各三层校验 |

**完成标准：**知道文档检索、SQL查询、函数执行如何配合；能指出模型只是提出工具调用，服务端执行；能解释RAG可以配合多跳查询，本体不会自动消除幻觉。

**可选第二小时：**20分钟读[[AI-05-Agent工作流MCP与Skills]]第1、4、6节；20分钟读[[AI-02-Prompt与上下文工程]]第2、4节；20分钟写一个有缺失信息、权限边界和失败返回的工具描述。

- [ ] 四任务技术选型完成
- [ ] 工具输入、结果、权限分开
- [ ] 能解释证据缺失时如何回答

## 第四天：把演示变成可验收的POC

| 时间 | 必做内容 | 产出 |
|---|---|---|
| 0–5分钟 | 回忆三种最危险的误承诺 | 写在页边 |
| 5–25分钟 | [[PRE-02-Demo工作坊与POC设计]]第1、3、5节；[[PRE-04-能力边界FDE协同与资产沉淀]]第1、4节 | 区分Demo、POC与生产 |
| 25–50分钟 | 用[[TPL-02-POC章程与验收矩阵]]填一页环卫POC | 用户、范围、基线、指标、样本、停止条件、下一步 |
| 50–60分钟 | 给POC增加3个失败案例，写FDE需要确认的问题 | 一个可决策问题包 |

**完成标准：**不以“客户觉得不错”作为唯一验收；不能把任何接口接通都叫轻开发；能说清楚本期不做什么、客户需提供什么、何时停止或升级评审。

**可选第二小时：**20分钟读[[AI-06-评测可观测性与成本性能]]第2–4、7节；20分钟读[[PRE-03-方案商业价值与技术异议]]第2–4节；20分钟给POC加成本口径，避免同一收益重复计算。

- [ ] 一页POC完成
- [ ] 3个反例和验收行为完成
- [ ] 一份FDE问题包完成

## 第五天：演练、查漏与准备入职沟通

| 时间 | 必做内容 | 产出 |
|---|---|---|
| 0–5分钟 | 回忆“数据→决策→动作→结果” | 不看稿复述 |
| 5–30分钟 | [[LAB-01-城市环卫闭环桌面演练]]第2–4节 | 给出推荐、排除理由、审批与失败行为 |
| 30–45分钟 | 按第6节录制3分钟讲解，重录一次 | 一段能独立讲顺的演示 |
| 45–55分钟 | [[REV-02-入职自测题与参考答案]]的必做题 | 找出最需要向同事请教的点 |
| 55–60分钟 | [[PLAN-02-入职后30-60-90天与产品确认清单]]选择3个首日问题 | 入职沟通便笺 |

**完成标准：**5项成果放在一起后，能讲清业务问题、数据对象、技术选择、POC标准和边界。没记住个别缩写可以查；如果会过度承诺、把模拟当真实，必须先改。

**可选第二小时：**20分钟运行离线练习或读代码；20分钟按[[CITY-03-跨行业方案迁移与技术选型]]迁移到补货；20分钟整理个人错题和首周需验证事项。不在最后一天为追求完整界面熬夜赶工。

- [ ] 模拟演练完成
- [ ] 讲解包含数据真实性与局限
- [ ] 三个首日确认问题准备好

## 时间不够时怎样取舍

只有5小时，直接按上面的必做表；别补第二小时。某天只剩30分钟，优先保留当天产出，用复习卡补机制；把未读深入段移到入职后，不把整天任务叠到第二天。卡在一个术语超过10分钟，把它记入个人错题，先继续完整业务链。

入职前无需系统推导Transformer训练、从头训练世界模型、精通所有数据库、重写Agent框架或搭整座城市平台。这些不对应当前最紧迫的五天成果。必要原理已经在母笔记里，遇到具体任务再深入。
