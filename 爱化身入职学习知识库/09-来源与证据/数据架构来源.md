## 1. 证据等级与使用原则

| 标记 | 证据类型 | 能支持什么 | 不能支持什么 |
|---|---|---|---|
| 公司一手材料 | 用户提供的介绍 PDF、官网 | 公司如何描述产品和技术路线 | 自动证明所有功能已在所有版本可用 |
| 官方技术规范 | W3C、IETF、数据库官方文档 | 相关技术的规范与机制 | 自动证明 Agentrix 使用某实现 |
| 原始研究 | 作者论文和研究机构发布 | 该研究的模型或方法 | 将论文结果迁移为公司产品性能 |
| 教学推演 | 本库原创场景及解释 | 帮助理解、练习与设计验证 | 真实客户事实、合同要求和收益保证 |

“官网说过”与“售前已验证”必须分开；“待核验”表示本次未取得相应证据，不表示公司一定没有该能力。

### AHS-W04：公开技术问答，建议入职前精读

[爱化身本体论闭门研讨会：11 个高管现场发问](https://www.aihuashen.com/pages/news/ontology-closed-door-seminar.html)，公司动态 **2026-06-26**。

**集中摘要：** 公司提出语义推断后由专家复核；规则层结合 OWL、机器学习建议和 LLM 例外处理；复杂工艺需专用预测模型，可由本体封装调用；当时 Skill 封装仍需技术人员。文中 OAG、“聚源类”为公司表达，需进一步核验具体实现。

原文定位：第 1 组问答看语义统一；第 2 组看规则引擎；第 3 组看专用预测；第 4 组最后一问看 Skill 当前边界。

**技术解读边界：** 该文公开了部分机制，不能写成“没有公开实现信息”。但“确定规则下的逻辑结果可重复”不能自动扩张为“含 ML、LLM、抽取、网络和物理执行的整个系统无误”。需要内部确认所用 OWL 子集/推理机、额外约束验证方式、例外审批、规则冲突和版本管理。这里的工程判断是本教材的分析，不是引述公司自证的结论。

## 3. 数据库与集成的一手技术资料

| ID | 来源 | 对应学习点 | 建议读法 |
|---|---|---|---|
| DB-01 | [PostgreSQL：Joins Between Tables](https://www.postgresql.org/docs/current/tutorial-join.html) | JOIN、LEFT JOIN、关联结果 | P0 看内外连接的差别，再回看本库工单 SQL |
| DB-02 | [PostgreSQL：Transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html) | 原子提交、撤销、可见性 | P0 理解单库事务边界，不把它扩张到外部设备 |
| DB-03 | [PostgreSQL：Using EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html) | 执行计划与实际执行 | P1；ANALYZE 会执行语句 |
| DB-04 | [Debezium PostgreSQL connector](https://debezium.io/documentation/reference/stable/connectors/postgresql.html) | 初始快照、变更日志、权限与恢复 | P1 看 Overview、How the connector works、故障章节 |
| INT-01 | [AWS：Transactional outbox pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html) | 业务更新与消息发布的一致性 | P1 配合重复派发和对账案例理解 |
| SEC-01 | [IETF RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) | OAuth 2.0 安全最佳实践 | 入职后按实际协议查，非五天背诵内容 |
| SEC-02 | [PostgreSQL：Row Security Policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html) | 数据行权限、绕过边界 | P1 对照服务账号及项目隔离检查 |
| OBS-01 | [OpenTelemetry：Traces](https://opentelemetry.io/docs/concepts/signals/traces/) | Trace 与 span | P1 理解如何关联一次业务请求各阶段 |

上表是通用工程学习资料，不代表公司采用 PostgreSQL、Debezium、AWS 或 OpenTelemetry。使用任一具体组件前还应确认版本、授权和交付支持。

## 4. 本体、图谱与 GraphRAG

| ID | 来源 | 重点 | 边界 |
|---|---|---|---|
| ONT-01 | [W3C OWL 2 Primer](https://www.w3.org/TR/owl2-primer/) | 类、属性、个体、逻辑公理和开放世界语义 | 通用标准，不等于公司全部规则执行机制 |
| ONT-02 | [W3C RDF 1.1 Primer](https://www.w3.org/TR/rdf11-primer/) | 三元组与图数据模型 | 技术入门 Note；不是完整规范总集 |
| ONT-03 | [W3C SHACL](https://www.w3.org/TR/shacl/) | RDF 数据形状与约束验证 | 与推理区分；未证实 Agentrix 使用 SHACL |
| ONT-04 | [W3C PROV Overview](https://www.w3.org/TR/prov-overview/) | 来源的实体、活动与主体 | 帮助理解血缘，不要求 POC 全套实现 |
| ONT-05 | [Palantir Ontology](https://www.palantir.com/docs/foundry/ontology/overview) | 企业本体的一种产品设计 | 仅作对照，不移植为爱化身事实 |
| ONT-06 | [Palantir Action types](https://www.palantir.com/docs/foundry/action-types/overview) | 动作类型与对象修改 | 供进一步比较动作契约，无兼容承诺 |
| GRAPH-01 | [微软 GraphRAG 查询概览](https://microsoft.github.io/graphrag/query/overview/) | 查询方式及适用问题 | 针对微软实现；GraphRAG 广义方案不都相同 |
| GRAPH-02 | [From Local to Global: A Graph RAG Approach to Query-Focused Summarization](https://arxiv.org/abs/2404.16130) | 图与社区摘要支持全局语料问题 | 研究结果不能等同任何图 RAG 的普遍收益 |

推荐顺序：先看本库教学例子，再读 OWL 的 classes/instances 与 RDF triples；GraphRAG 先看 query overview，再按需要读论文。无需五天内掌握所有语义网语法。

## 5. 世界模型、数字孪生、因果和优化

| ID | 来源 | 用来澄清什么 | 阅读级别 |
|---|---|---|---|
| WM-01 | [Ha & Schmidhuber：World Models](https://arxiv.org/abs/1803.10122) | 学术世界模型的一条研究路径 | P1/P2，先看摘要和方法图 |
| WM-02 | [Hafner 等：Mastering Diverse Domains through World Models](https://arxiv.org/abs/2301.04104) | DreamerV3 通过学习世界模型支持决策的例子 | P2；不能据此认定公司用了 Dreamer |
| DT-01 | [NIST：Digital twin 术语页](https://csrc.nist.gov/glossary/term/digital_twin) | 数字表示与真实实体的联系 | P1，并按原报告理解语境 |
| DT-02 | [NIST：Definitions and State of the Art](https://www.nist.gov/digital-twins/definitions-and-state-art) | 不同领域的定义差异与数据联系 | P1；仅有三维模型不证明完整动态能力 |
| CAUSAL-01 | [Pearl：Causal Inference](https://proceedings.mlr.press/v6/pearl10a.html) | 结构因果模型、干预和反事实的理论边界 | P2；本库班组/投诉例子为原创 |
| OPT-01 | [Google OR-Tools：Vehicle Routing Problem](https://developers.google.com/optimization/routing/vrp) | 多车路径目标及约束建模 | P1 看目标和约束；实战时再跑官方例子 |

这些资料用来建立通用技术边界，不是爱化身 WBM 的论文清单。也没有发现可据此证明公司 WBM 与某一标准算法等同的证据。
