# 入职谈话术语与口径

| 术语 | 本次谈话中的含义 | 需要继续核验 |
|---|---|---|
| 本体 Ontology | 将企业中的对象、关系、动作与底层数据建立统一业务语义 | 公司正式对象模型、建模流程和产品界面 |
| 对象 | 员工、车辆、订单、项目等业务实体 | 类型、实例和身份解析机制 |
| 关系 | 对象之间的业务连接，如员工—岗位、车辆—任务 | 时效性、权限和关系维护方式 |
| 动作 Action | 对对象执行或触发的业务行为，如派单、调度、审批 | 动作协议、审批、幂等和回滚 |
| DataOS | 数据接入、治理、本体和业务语义的基础平台 | 当前版本、标准模块和客户部署形态 |
| AgentOS | 建立在业务本体之上的智能体运行与协同平台 | 与现有产品三层架构的正式命名关系 |
| Agent Workforce | 面向岗位或业务流程的智能劳动力/智能体应用 | 会议中提及较少，参考公司正式材料 |
| RAG | 从资料中检索相关内容，再交给模型生成答案 | 与公司本体路线的准确边界，不使用“RAG 一定不可靠”等绝对表述 |
| 经营面 | CEO 关注的收入、成本、利润、效率、风险和决策 | 各行业的核心经营指标体系 |
| 作业面 | 一线生产、调度、设备、服务和现场执行过程 | 行业设备、专业算法和控制风险 |
| 实控人 | 对企业拥有实质控制和重大决策权的人 | 与董事长、CEO、投资人的具体关系因企业而异 |
| 会客 | 参与或承担真实客户会面、沟通和汇报 | 第一月具体承担旁听、主讲还是主持待确认 |
| 业务叙事 | 用经营、资本和未来图景解释方案价值 | 公司优秀对客材料与话术样例 |
| 强势文化 | 以更高专业认知定义客户变革路径，而非蛮横压制客户 | 对外表达需避免造成“无视客户需求”的误解 |
| Owner 意识 | 对目标进行拆解、调资源、执行、交付和复盘，对结果负责 | 各类任务的授权边界和评审节点 |
| 行业 know-how | 对行业经营、流程、规则、指标、约束和关键角色的真实理解 | 每个项目需要形成证据来源和专家校验 |
| POC | 用有限范围验证关键业务价值与技术可行性 | 公司正式立项、投入和验收口径 |
| FD/FDE | 进入现场推进交付或前置工程工作的角色 | 公司内部正式名称和职责边界 |
| Skill | 把个人或团队经验沉淀成可复用的 AI 工作方法/应用包 | 公司平台的格式、发布和治理方式 |
| 世界行为模型 | 谈话中指向企业行为知识、预测/行动能力的长期模型方向 | 输入输出、训练机制、产品边界和对外可讲口径 |

## 表达注意事项

- “本体比 RAG 高级”不够准确，应说明两者解决的问题不同，也可能组合使用。
- “零幻觉”“100% 准确”等绝对词需谨慎，除非有正式评测证据。
- “系统已接管企业”“成本节省四分之一”等案例数字只能在获得批准和证据后对外使用。
- 面向 CEO 先讲经营价值，面向 CTO 再展开数据、接口、权限、可靠性和技术边界。
